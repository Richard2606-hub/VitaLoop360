# Proposal requirements and implementation scope

Source: the supplied `01_VitaLoop360_Proposal.docx` and its extracted text. This document compares product behavior with that proposal; it does not validate the proposal's external event, legal, pricing, or platform claims.

**Implemented** means a local code path exists. **Partial** means a bounded subset or demonstration exists. **External/unverified** requires infrastructure, data, access, or evidence not supplied. **Roadmap** is not implemented as the proposal's complete feature.

| Proposal requirement | Status in this build | Evidence and remaining work |
| --- | --- | --- |
| One shared console and lot identity | Implemented locally | Python runtime serves the browser console and reconstructs lot events. The synthetic incident flow is specifically lot `2610-07`; `2610-05` is illustrative reserve stock. This is not a general MES/ERP adapter. |
| Factory energy/scrap metrics and waste index | Implemented on synthetic input | `backend/calculations.py` computes energy intensity, scrap, idle share, reactive ratio, weighted waste index, and estimated excess energy cost. See [factory methodology](factory-methodology.md). No licensed public or plant dataset is incorporated. |
| Robust MAD and Isolation Forest anomaly flags | Implemented as diagnostic demonstration | Robust energy score plus a small seeded, dependency-free Isolation Forest over the sample shift. No independent benchmark or industrial calibration is supplied. |
| Model gateway with interchangeable compatible endpoints | Partial | Server-side chat-completions request, environment configuration, bounded concurrency, local rate limit, retries, timeout, response checks, and request cache. Actual endpoint compatibility must be tested with operator credentials. |
| Gemma running on AMD, including self-hosted ROCm/vLLM | External/unverified | The gateway can target a compatible deployment. No AMD key, verified deployment, model availability confirmation, or real AMD run was supplied. A configured provider name cannot attest hardware. |
| Locked facts and source verification | Implemented locally | `backend/verification.py` enforces numeric membership against locked facts, citation resolution (`[DOC-ID]` and `[FACT:key]`), 100% sentence citation coverage, and identifier locking (`SOP-*`, `IFU-*`, `PO-*`, `INV-*`, `GRN-*`, `ORD-*`, `2610-*`, `Lot NNNN-NN`), plus interactive custom/preset adversarial draft testing in Factory Sentinel. |
| Scoped lexical evidence retrieval | Implemented locally | BM25-style passage scoring filters by pack and optional version. Sources are an authored in-memory fixture catalog and `packs/*/docs/*.md`. |
| One directed regeneration then refusal | Implemented factory path | The runtime retries a model draft with named findings and withholds a repeated failure. No configured live endpoint was exercised by the offline build checks. |
| Human approval before consequences | Implemented locally | Named actor and evidence notes gate local hold, release, corrective work, downstream approvals, and simulated nurse review resolution (`nurse_resolve`). Release requires corrective approval after the latest hold. |
| SHA-256 audit ledger and materialised views | Implemented locally | JSONL records chain to the previous digest; invalid on-disk chains block appends. `ledger.views()` materialises `cost_view`, `verification_view`, `guard_view`, `approvals_view`, and `lot_view`. |
| Shared event thread | Implemented locally | Manifest-declared event types, subscriber metadata, local lot history, and downstream approval projections across all 5 capability packs. |
| Installable packs and quarantine | Implemented locally | `packs/{factory,order,demand,experience,care}` each contain `manifest.json`, `rules.json`, `schemas/*.json`, `prompts/*.txt`, `docs/*.md`, and `readiness/cases.json`. `discover_pack_folders()` validates manifests and quarantines broken packs. |
| Cost and inference telemetry | Implemented locally | Configured-model responses supply token usage and measured request latency; `/api/metrics` and `python run.py --metrics` report full Proposal Section 11 metrics. |
| Privacy redaction and sensitive-data policy | Implemented locally | Deterministic PII redaction (`redact_pii` / `browserRedactPii`) scrubs `EMAIL`, `PHONE`, `ID`, `ADDRESS`, and `PERSON` entities before processing; raw caregiver free text is never stored in the ledger. |
| Compliance and Order Hub | Implemented walkthrough | Multilingual (IT/EN/BM) PO, Goods Receipt, Invoice, and Quality Certificate inspection, deterministic three-way match (`three_way_match_calc`), tolerance slider, cited dispute note (`[TERMS-008-v1.0-3]`), and reserve lot `2610-05` allocation. |
| Demand and Retention Brain | Implemented walkthrough | Additive Holt-Winters triple exponential smoothing ($\alpha=0.35, \beta=0.10, \gamma=0.25, m=7$) with held-out MAE/RMSE/MAPE backtest against Seasonal Naive baseline, safety stock & reorder point, RFM segmentation, and Weibull survival churn hazard $S(t)=\exp(-(t/\lambda)^k)$ with expected net value per customer. |
| Adaptive Unboxing Studio | Implemented walkthrough | Audience (`caregiver`/`active`), language (`en`/`ms`/`it`), and branch (`quick`/`detailed`) storyboard preview with deterministic style-bible quality gate (`BRAND-v1.0-2`) blocking prohibited clinical/health claims, unit economics card, and automatic `instructions.bound` emission. |
| SafeCare Navigator | Implemented walkthrough | Versioned `IFU-v2.1` retrieval, multilingual (EN/BM/IT) deterministic clinical-boundary refusal and red-flag escalation (`care_guard`), independent dual-extractor agreement indicator (`care_agreement`), PII redaction preview, and simulated nurse review queue resolution. |
| Serve, recorded replay, and batch readiness modes | Implemented locally | `run.py` supports `--mode {serve,replay,batch}`, `--replay <ledger.jsonl>` (read-only ledger inspection), `--batch` (18-case happy-path + adversarial twin readiness suite), `--metrics`, and `--export-demo`. |
| Public submission and portfolio | External/unverified | Local source and documentation are provided. Actual event submission, public repository, video, slides, external URL validation, and six separately released repositories are separate deliverables. |

## Validation boundary

The automated test command and manual acceptance checklist are in the [README](../README.md). Test execution verifies only the code paths and fixtures covered. A successful local run does not establish hackathon eligibility, regulatory compliance, clinical suitability, industrial effectiveness, or compatibility with an untested external endpoint.

Before a later release changes a walkthrough badge to a live capability, implement and test that pack's complete rules and integrations, update [data provenance](data-provenance.md), and retain real run evidence. This follows the proposal's explicit priority: a completed hero flow with honestly labelled downstream scope.
